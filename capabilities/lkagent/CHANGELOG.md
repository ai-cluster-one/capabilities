# lkagent — change log

## 2026-11-27 — A recorded call's audio and session report go to lkagent's own storage, under a set folder, and its row says where

With `recording` on, the line recorded each call's session and then had nowhere to put it: lkagent handed callva-livekit no storage, its script did not install boto3, and the call's row kept no key, so the audio was lost and nobody could find it. The connection now carries the line's own recording storage beside its LiveKit server, all optional - `recording_bucket`, `recording_endpoint`, `recording_region`, and the keys `recording_access_key_id_env` and `recording_secret_access_key_env`, whose values `lkagent connection add --stdin` (with `--replace` on a connection that exists) seals into the agent's vault - and the new setting `recording_folder` (default `calls/lkagent`) names the folder in that bucket. Nothing is taken from another capability's storage. `service run` hands them to callva-livekit as `RECORDING_S3_*`, so each recorded call leaves `<folder>/<call id>.ogg` (stereo audio) and `<folder>/<call id>.session.json` (the session report), and the script now declares `callva-livekit[s3]>=0.1.74`, so uv installs boto3 at the service's next start.

`lkagent_calls` gains `audio_key` and `session_report_key` (tables 1.1, an added step), filled from the `recording` object of the `call.ended` body; `recording_url` is unchanged. With `recording` on and the bucket, either key or the folder missing, nothing is recorded - never into the bucket's root - the worker still takes calls and says why on its log, `lkagent doctor` fails its new `recording` check naming what is missing, and `service doctor` reports the same under `recording` without failing. No secret is printed or written to settings.

## 2026-11-27 — lkagent's line runs under the node supervisor, reads its log, keys its numbers by the number, and reaches OpenAI where the key's project is served

`capabilities node supervise lkagent` refused the line with `no_service` (`lkagent's service declares no deploy command`), so a node ran it only where somebody started it by hand and nothing brought it back after a restart. The service now declares `service.deploy`: `lkagent service run` is its command and `lkagent service doctor` its doctor, so the node's supervisor runs it where the node's gate places it. The service gains `service status` (whether the recorded worker is alive, and since when) and `service logs [--tail N]` (the end of `service.log` in the line's state directory, which `service run` appends everything the worker and its calls log to); `service logs` answered `invalid choice: logs` before.

The `numbers` setting is an object keyed by the number in E.164 - `{"+15550100": {instructions, allowed_capabilities, read_only}}` - so a number's configuration is found by the number itself. A line that kept its numbers as the list they were kept as before is read as it was, and `service run` writes that list keyed once, every entry whole; a list the line's own check refuses is left as it is. `lkagent settings set numbers` takes the keyed form.

The voice reached OpenAI only at api.openai.com, so a key of a project served elsewhere - an EU project, served at `https://eu.api.openai.com/v1` - was refused and the call dropped. `service run` now resolves `OPENAI_BASE_URL` through the credential cascade, the agent's vault first, and gives it to GPT Live beside the key; `service doctor` shows it as `openai_base_url`. Unset, nothing changes.

## 2026-11-26 — LiveKit Agent shows LiveKit's mark, not a phone glyph

`lkagent` declared the Lucide icon `phone` beside its `icon.png`, and a reader that draws a declared Lucide glyph before the capability's own picture showed a plain outlined phone. Its icon is LiveKit's brand mark, and a capability whose icon is a brand mark declares no Lucide icon, so `lkagent` no longer declares `LUCIDE_ICON`: the manifest and the catalogue entry carry `icon: true` and no `lucide_icon`, and `icon.png` is unchanged. Nothing else changes.

## 2026-11-26 — lkagent: an agent's own phone line on LiveKit, GPT Live as the voice and the agent's own harness session as the backend

A new capability, `lkagent`, titled LiveKit Agent. `lkagent service run` registers a LiveKit worker under the line's agent name (the `agent_name` setting, else `lkagent-<connection id>`) and answers the calls dispatched to it, one at a time. GPT Live, under client delegation, is the voice; each turn it hands over is written at once into one live Claude process kept for the whole call (or a resumed Codex session), and the backend's steps reach the voice as thinking notes while it works. The call opens as `agent_speaks_first`, `greeting_type` and the greeting settings say, ends at `max_duration_seconds` or on silence, and a silent line is a backend turn told its instruction first and then what was said, all through callva-livekit, which also reports each call to `webhook_url`.

A connection is one LiveKit server: `url`, `api_key_env` and `secret_env`. The OpenAI key is the machine's `OPENAI_API_KEY` setup field, shared and resolved from the agent's vault first. A call is taken only on one of the line's `numbers`, each `{number, instructions, allowed_capabilities, read_only}`: an inbound call on the number it called, an outbound one on the number it is placed from, and the backend runs under that number's instructions and rights; a call on any other number is hung up at once and recorded as failed. `lkagent call <number>` dials through the `outbound_trunk` setting from `--from`, one of the line's numbers. Recording is off unless `recording` is set. Each finished call is a row of `lkagent_calls` in the project's store, read from the `call.ended` body; a project without a store records nothing and says so once. `doctor` and `inventory --network` read the SIP dispatch rules routing to the line and the numbers they route, and `doctor` warns when none does. The guide `twilio-number` connects a Twilio number to the line. The bundle carries LiveKit's mark as its `icon.png`, taken unaltered from LiveKit's GitHub organisation avatar (256 x 256); the mark is LiveKit's trademark, used only to identify the service the capability reaches.
