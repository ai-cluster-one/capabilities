# Writing memory entries

How to decide what belongs in memory, and how to write an entry that is still useful when a later session reads only its title.

## What an entry is

An entry is one conclusion that should govern work not yet done and has no other home yet. An account of what a run did belongs in that run's own record, a procedure belongs in a routine, and a settled rule belongs in the project's doctrine. Memory holds the conclusion until it has one of those homes, and the drop that retires it names where it went.

## The title carries the conclusion

A session meets an entry as one index line in a search or a list, so the title states the conclusion itself rather than its topic: "Bare dates are read as UTC" serves a reader who never opens the entry, "Notes on dates" does not. The text then gives the reason, the evidence it rests on and where that evidence lives, in a few sentences.

## Decisions are quoted, and the lasting ones move to doctrine

When the owner of the project decides something, record it as an entry and quote their words exactly as they said them inside quotation marks; a grooming pass that would lose a quotation is refused, so quoting is what keeps the words intact. Pin it to keep it out of grooming passes altogether. Every session reaches an entry through search, so a decision every session must hold is promoted into the project's doctrine, and the entry is dropped naming where it went.

## Changing your mind

An entry's text never changes. When a conclusion changes, supersede the old entry with a new one that states the conclusion as it now stands, and give the reason; the old entry stays readable in its trail. When a conclusion simply stops holding, drop it with the reason, and when it was promoted into doctrine, a routine or a task, name that destination so a reader can follow it.

## A secret written by mistake

A secret never belongs in memory. If one lands there, drop the entry with its whole id and the purge option: it is the one deletion the store allows, and it leaves the trail without the text. Then rotate the secret, since it was readable while it stood.

## Reading back

The block in context carries no entry: it says how to record and how to search, how many active entries there are and when the newest was written. Search is how an entry is reached, showing one gives its whole text and trail, and listing since the newest moment the block names shows what was recorded after the session began. When answering a question would take more than one lookup, hand the search to a subagent that returns only its conclusion, so the reading does not crowd the session. `memory help` states every verb and option.
